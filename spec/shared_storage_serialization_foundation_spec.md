# Shared Storage, Serialization, and Schema Strategy Foundation Spec

Status: Implemented
Owner: grumpy runtime
Target: shared contracts reused by query cache and repo state persistence

## 1. Purpose

Define a single source of truth for cross-cutting contracts used by:

- `multi_layer_cache_pipeline_spec.md`
- `repo_state_persistence_and_bootstrap_sync_spec.md`

This avoids drift across duplicated definitions for storage keys, serialization codecs, and schema-mismatch handling.

## 2. Scope

This spec standardizes:

1. storage key contracts
2. serialization codec contracts
3. schema versioning/fingerprinting model
4. schema mismatch resolver strategy contract

## 3. Core Contracts

### 3.1 Storage Key Contract

```dart
abstract class StorageKey {
  /// Logical key namespace (repo/module/domain partitioning).
  String get namespace;

  /// Stable per-item/per-query identifier within namespace.
  String get primaryKey;

  /// Auto-generated schema fingerprint for serialized data shape.
  String get schemaId;

  /// Optional manual compatibility channel for migration windows.
  int? get compatVersion;

  /// Stable persisted key representation.
  String asStorageKey();
}
```

Recommended default key format:

`$namespace|$schemaId|c=$compatVersion|$primaryKey`

(omit `|c=...` when `compatVersion == null`)

### 3.2 Serialization Codec Contract

```dart
typedef JsonMap = Map<String, Object?>;

abstract class SerializationCodec<Data, Serialized extends Object> {
  Serialized encode(Data value);
  Data decode(Serialized payload);
}
```

Guidance:

- default persistent implementations should support at least `String` and `JsonMap`
- additional wire formats are adapter-specific and opt-in

### 3.3 Schema Fingerprinting Model

1. `schemaId` should be auto-generated by source generation from serialized model shape.
2. Developers should not manually bump schema identifiers in normal flows.
3. `compatVersion` is manual and optional, used only for intentional compatibility windows.
4. If schema generation is unavailable, require explicit `schemaId` declaration.

## 4. Schema Mismatch Strategy Contract

```dart
class SchemaMismatchContext<Serialized extends Object> {
  const SchemaMismatchContext({
    required this.storageKey,
    required this.expectedSchemaId,
    required this.foundSchemaId,
    this.serializedPayload,
    this.compatVersion,
    this.error,
  });

  final String storageKey;
  final String expectedSchemaId;
  final String? foundSchemaId;
  final Serialized? serializedPayload;
  final int? compatVersion;
  final Object? error;
}

class SchemaMismatchDecision<Serialized extends Object> {
  const SchemaMismatchDecision({
    this.evict = true,
    this.treatAsMiss = true,
    this.allowDecodeFallback = false,
    this.patchedSerializedPayload,
  });

  /// Remove/delete mismatched persisted data.
  final bool evict;

  /// Continue with normal miss path.
  final bool treatAsMiss;

  /// Attempt decode with original or patched payload.
  final bool allowDecodeFallback;

  /// Optional patched serialized payload used when fallback decode is enabled.
  final Serialized? patchedSerializedPayload;
}

typedef SchemaMismatchResolver<Serialized extends Object> =
    FutureOr<SchemaMismatchDecision<Serialized>> Function(
      SchemaMismatchContext<Serialized> context,
    );
```

Default resolver recommendation:

- evict mismatched data
- treat as miss
- do not decode fallback

Advanced use:

- inspect `serializedPayload` for migration heuristics
- return `patchedSerializedPayload` + `allowDecodeFallback=true`

## 5. Integration Rules for Consumer Specs

1. Consumer specs should reference these shared contracts instead of redefining them.
2. Consumer specs may define context-specific wrappers/adapters, but not conflicting base contracts.
3. Consumer-specific policy objects may include
   `SchemaMismatchResolver<Serialized>?` for overrides.
4. Behavior differences (cache vs snapshot delete semantics) should be expressed in policy/default resolver wiring, not by redefining contract shape.

## 6. File Layout Guidance

Potential shared runtime files:

- `lib/src/domain/models/storage_key.dart`
- `lib/src/utils/serialization_codec.dart`
- `lib/src/domain/models/schema_mismatch_strategy.dart`

Consumer runtimes import these rather than duplicating definitions.
